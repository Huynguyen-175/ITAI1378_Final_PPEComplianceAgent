## B. Pipeline Mechanics Validation (agent code, not model accuracy)

The files below (`images/`, `traces/`, `metrics.txt`, `robustness_test_evidence/`) were
generated by actually running `agents/ppe_compliance_agent.py` end-to-end — but **using
the fallback generic YOLOv8n weights**, not the fine-tuned PPE model (the trained weight
file is too large to commit and wasn't available in the build/test environment). These
demonstrate that the *pipeline itself* works correctly:

- `traces/*.json` — full 6-stage trace per image (ingestion → preprocessing → perception → reasoning → action → logging)
- `images/*_annotated.jpg` — annotated output images with compliance-status banners
- `metrics.txt` — batch summary (status counts, average latency)
- `robustness_test_evidence/` — proof the agent handles bad inputs gracefully: a corrupt file and an undersized image were both caught and `SKIPPED_INVALID_INPUT` rather than crashing the batch; a valid-but-blank image was processed normally and correctly returned `NO_DETECTION`

Because these traces used fallback weights (generic COCO classes, no mask/no-mask
classes), the compliance decisions in this batch show `NO_DETECTION` — **this is
expected**, not a bug. It demonstrates the reasoning stage correctly abstains rather
than guessing when the perception stage has nothing relevant to report.

**To get real system-level results:** place `best_yolov8n_ppe.pt` in `models/trained/`
(see `models/README.md`) and re-run `notebooks/02_evaluation.ipynb` — the same code path
will then produce real compliant/non-compliant decisions instead of abstentions, and the
task-success-rate comparison against ground truth becomes meaningful.
